## A guarded project workflow

<CardGrid stagger>
	<Card title="One project, one sandbox" icon="rocket">
		sbxm gives every registered GitHub project its own Docker Sandbox and keeps the host clone and project metadata together.
	</Card>
	<Card title="Predictable worktrees" icon="open-book">
		Use an attached worktree or create up to 32 detached worktrees for independent agents and tasks.
	</Card>
	<Card title="Credentials stay outside" icon="lock-closed">
		GitHub credentials use Docker Sandboxes’ secret proxy. The real token is not copied into the sandbox.
	</Card>
	<Card title="A guarded lifecycle" icon="setting">
		Register, prepare, open, inspect, rebuild, stop, and destroy projects with explicit safety checks.
	</Card>
</CardGrid>

## What sbxm keeps separate

<div class="my-8 grid gap-4 rounded-2xl border border-accent-200 bg-accent-50 p-6 text-sm dark:border-accent-800 dark:bg-accent-950/30 md:grid-cols-3">
	<div>
		<strong class="block text-accent-800 dark:text-accent-200">Host</strong>
		<span>Clone, Dockerfile, metadata, and registry remain on the host.</span>
	</div>
	<div>
		<strong class="block text-accent-800 dark:text-accent-200">Sandbox</strong>
		<span>Repository setup and managed worktrees live inside the Docker Sandbox.</span>
	</div>
	<div>
		<strong class="block text-accent-800 dark:text-accent-200">Proxy</strong>
		<span>The secret proxy supplies GitHub credentials only to registered hosts.</span>
	</div>
</div>

## Built for the supported host

sbxm currently targets macOS 14 or later on Apple silicon with Docker Desktop, Docker Sandboxes CLI 0.37.0 or later, Git, SSH, and a repository-scoped GitHub personal access token.
