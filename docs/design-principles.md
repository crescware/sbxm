# sbxmの設計原則

この文書では、sbxmの各機能に共通して適用する設計方針を定める。

## この文書が扱う範囲

この文書に記載するのは、使用するプログラミング言語や実装技術にかかわらず、sbxm全体に共通して適用できる原則に限る。特定の言語や技術に固有のコーディング規約や設計規約、構造体や関数など個別の実装要素の設計方法は、この文書の対象としない。必要な場合は、各機能の仕様書や実装に対応する文書で定める。

## 曖昧な状態では利用者にとって安全な挙動を選ぶ

sbxmは、外部の状態や永続化された状態、利用者の意図を一意に判断できない場合、その曖昧さを安全の根拠にしない。状態を変更しても安全だと確認できない限り、変更を伴う操作を続行しない。

具体的には、次を共通方針とする。

- 複数の解釈が成り立つ入力や状態について、名前、パス、現在の作業ディレクトリ、類似する値などを手がかりに、推測で補わない
- 正本同士に食い違いがある場合、どちらか一方を正しいとみなして暗黙に修復しない
- 所有関係または対応関係を確認できない既存の成果物は、名前が一致するという理由だけで管理対象に取り込んだり、上書きしたり、移動したり、削除したりしない
- 外部の状態を観測できない場合、それを「存在しない」「一致している」「安全である」のいずれかとみなさない
- 状態を安全に変更するための条件を満たしていない場合、変更前に操作を拒否し、観測できた事実をエラーメッセージで示す
- 自動修復を提供する場合、通常の操作の一部として推測で実行しない。対象、根拠、変更範囲を明示した専用の操作手順として設計する

利便性を理由に、個別の機能でこの方針を暗黙に緩めてはならない。例外が必要な場合は、その機能の仕様に、曖昧さのない判定条件と許可する状態変更を明記する。
